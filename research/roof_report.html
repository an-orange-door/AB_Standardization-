What we are building

Something like KitBash but where you are not constrained by baked models with weird proportions. Jordan Halsey, 15 August 2026

The inverse of a model store: procedural, standards-based, artist-controlled, optimised — and credible because the tools came out of years of production rather than being designed for a storefront.

Today the strongest tools are signage, the more finished city props, and the door and window tool — whose framework is cheap to extend, which makes it unusually high return per hour. The named gap is that buildings need to increase in complexity. And the thing KitBash sells that we do not yet do systematically is decorating — which is exactly what RooftopProcessor is to a roof and SidewalkProcessor is to a sidewalk. That pattern generalised is what turns a shape into a place.

The through-line: classify, don't enumerate

Every subsystem here reduces to the same move. A shape arrives as a polygon, and the tool must derive its parts by measurement instead of having a human name them one at a time.

One classification layer, two subsystems

Per vertex — turn angle, and the sign of the cross product giving convex versus reflex.
Per edge — length, direction, and its relation to its neighbours.

That is simultaneously the footprint's corner-and-wall classification and the roof's per-edge weight vector, because we = cot θe makes per-edge pitch a per-edge weight. Build it once.

The corner problem

There are two corner mechanisms in the tool and they cannot meet.

The hand-built shapes name their corners. BaseFromCurve cannot, so it does something else: resample the curve at BaseModSize, copy a sphere onto each original curve point, and group the resampled points falling inside it. measured

The instinct is right. Four things limit it:

  • The sphere is a fixed absolute size — radius 0.5 × scale 0.1, about 0.05 units. It does not scale with BldCornerSize (3.0) or with the resample length, so corner capture is a constant radius at any building size.
  • It cannot measure the corner angle. A 90° corner and a 175° near-straight vertex group identically, so treatment can never vary by sharpness — which is exactly what real architecture does.
  • It cannot detect reflex corners. An L's inner corner needs an inner fillet, not an outer chamfer. Opposite operations.
  • It groups points, not edges — so there is no per-wall classification at all.

That last one is the real ceiling. Downstream modules consume MF_walls, BldBase, BldCorners and extrudePlane — those group names are the contract, and a curve input can never produce them.

The classification layer

Compute what is currently named. For any closed planar polygon:

Emit f@corner_angle, i@corner_convex, i@wall_id, and pick the corner treatment from a catalog keyed by angle band — the same column lookup as SignLibrary's SizeClass. That yields U, T, cross, courtyard and arbitrary curves with zero new subnets, and promotes BaseFromCurve from a degraded path to the primary one.

The constraint that governs the build

Keep emitting the existing group names. WallLeft, Corner_01, BldCorners — generate them from the classification rather than authoring them, or every downstream building tool breaks. The verification test writes itself: an N-gon must yield N wall groups and N corner groups, and Square and L must reproduce their current groups exactly.

Roofs — four operators

The same classification, lifted. Four operators span the whole typology, and the first absorbs fourteen of eighteen named forms with no branching.

  1. SKELETON — a weighted straight skeleton, lifted by a banded section profile. Footprint, per-edge weight vector, ordered bands.
  2. SWEEP — a periodic section along an axis, clipped. Sawtooth, folded plate, monitors, vaults.
  3. INSERT — a sub-mass booleaned into a face. Dormers, bulkheads, tanks, cupolas.
  4. TRIM — a profile swept along a classified edge: eave, rake, ridge, hip, valley, coping. All of STYLE lives here.

The hinge identity

we = cot θe

Per-edge pitch is per-edge wavefront speed — which is why the footprint's edge classification is already the roof's input. Set two weights to zero and a hip becomes a gable; three, a shed. Hip-and-valley and cross-gable stop being types at all.

And the band profile in (run, rise) is a moulding profile — same curve, same authoring problem. The ten composable elements written for the WM catalog become the roof section library. Third use of one pattern.

Wing 4.0 ft, main block 5.0 ft — the deeper mass rides higher at a single pitch, and a framer gets the same answer. Matching them needs m = 5/8 = 7.5:12 on the wing derived, which is the canonical reason to reach for the weighted skeleton and a one-line rule the tool can offer as a button.

Rectilinear footprints are the degenerate case, not the general one

At t = 8 the reflex vertex's split event and an edge collapse happen simultaneously — and for any rectilinear L they always do, at t = min(w,h)/2. derived Building footprints are overwhelmingly rectilinear, so the case theory treats as a rare coincidence is the normal input. Deterministic tie-breaking is a prerequisite.

NYC ZR 23-421 is a straight skeleton written into law

Walls to 25 ft, then planes converging on a 35 ft ridge, max face angle 80°. Pitch is not a style choice — it is a consequence of plan depth, atan(10/(D/2)). The regulation and the geometry are the same object.

One caveat: the sky exposure plane that produced Manhattan's stepped ziggurats was demoted to opt-in on 5 December 2024. It explains what is standing, not what gets built now.

IRC R905 gives a citable floor on pitch per covering — slate 4:12, asphalt 2:12, standing seam ¼:12 cited. That is the honest way to clamp a pitch slider: not an arbitrary minimum, but the slope below which the material is not permitted.

Order of work

Houdini already ships the core algorithm. polyexpand2d computes the weighted straight skeleton natively — its Inside Scale attribute is cot θe. Across all 155 tools it appears exactly once, in CommercialSignGenerator 4.8. measured So this is wiring, not implementing.

  1. The classification layer — vertex angle, convex/reflex, edge id. Serves footprints and roofs both; nothing else can start cleanly without it.
  2. AB::BuildingFootprints::1.0 — replaces 277 nodes and three dead subnets, and makes BaseFromCurve primary.
  3. Doors and windows — highest-rated tool, cheapest to extend, and exercises all three axes.
  4. Roof SKELETON + TRIM — form, then style.
  5. The processor / decorating family — the product surface, not a tidy-up phase.

Catalog versus parameter

  • Catalog CSV — covering minimum slopes, code height and parapet limits per city, standard door and window sizes, corner treatments by angle band. Facts, citable, versioned. Same pattern as signs, hardware and mouldings.
  • Parameter — pitch, break height, corner size, which edges are gable. Per-instance choices.
  • TYPOLOGY sets dimensions; STYLE is the TRIM operator and must never move the bounding box; VARIATION is sag, patching and replacement.

The verification test

  • N-gon in → N wall groups and N corner groups; Square and L reproduce their current groups exactly.
  • Face count = input edge count.
  • Plan areas sum to the footprint, residual zero.
  • Surface = plan / cos θ at uniform pitch.
  • No vertex below grade — the naive tilted-planes construction fails this on an L.

What this approach cannot do

  • Dormers, sawtooth and folded plate are not footprint problems. Their generators — a room, a direction, a period — are not in the perimeter.
  • Curved and freeform roofs fall outside a straight-skeleton construction by definition.
  • Structure is not solved by generating the surface. Spans, load paths and truss selection are a separate layer.
  • Historical accuracy is not geometric accuracy. The skeleton will happily produce a shape no builder of that period would have framed.
  • Set dressing is not worth proceduralising where it can be hard-surface modelled faster by hand. The procedural investment belongs where proportion and variation matter.
