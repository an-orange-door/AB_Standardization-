The one that can stop a release outright

3.3 GB of embedded textures with unverified provenance, inside files intended for sale. PolyHaven is CC0 and shippable; Megascans is not, under any circumstances. Nothing else on this page matters until that is traced.

How the work is split

48 tracked items, each carrying its own action. The split matters more than the count: most of the volume is mechanical, and the human time goes into a much smaller set of judgement calls.

Decisions are tracked in a shared sheet with a stable ID per row (AB-001 … AB-048), so any item can be referred to by number and its resolution recorded next to it.

02

The stages

01WEEK 1

Licensing and provenance

Trace every embedded texture to CC0 or in-house. Anything unverified is replaced or regenerated, not shipped. This gates everything downstream, because a texture that cannot ship should never be extracted, deduplicated, bound, or documented.

GATE · every shipped texture traceable · LICENSE and attribution file exists
02WEEK 1–2

Textures out, references repaired

Extract 43 unique textures to a shared folder, delete the 8 orphans, and repoint every opdef: path. This is the single highest-value job in the plan: it repairs 96 currently-broken references, removes 91% of library bytes, ends the LFS problem, and eliminates a URI scheme no renderer has ever supported reliably.

GATE · every asset cooks identically · all textures resolve on disk · no opdef: remains
03WEEK 2

Identity and version hygiene

Resolve the 12 filename/type mismatches, fix the misspellings baked into type names (MModulesArtDeco, Satelite, VDBooleans), repoint or remove the 8 missing nested types, and collapse the version sprawl to one shipping version per tool with the rest archived outside the scan path.

Type-name changes are breaking — any scene referencing the old name loses the node. That makes this the last safe moment to do it.

GATE · filename matches type everywhere · one shipping version per tool · no dangling nested types
04WEEK 3

Tiering and the standard interface

Not every tool should carry all eight standard parameters — a scatter does not need lightmap UVs, and a volume tool must be excluded from zone canonicalisation entirely. Assign tiers, then inject per tier.

  • Tier 1 ≈ 77 geometry producers — full interface and export chain
  • Tier 2 ≈ 31 point and curve emitters — documented attribute contract instead
  • Tier 3 ≈ 38 volumes, VFX, motion graphics — exempt, and hard-blocked from the canonicaliser
GATE · every tool tiered · compliance rises per category · one commit per category
05WEEK 3–5

Materials that actually work

124 of 161 zones already bind to CC0 materials. The gap is concentrated and specific: metal is 41% of all shading zones with almost no CC0 coverage. That is not 61 materials to source — it is roughly 8 base metal looks authored in Copernicus and varied per zone with wear and edge masks.

Glass, emissive and signage are not scanned materials at all; they are shaders and artwork, and the artwork carries its own licensing question.

GATE · every zone maps to a material or is explicitly marked shader-only
06WEEK 5–6

The USD half

USD currently exports correct geometry with no materials whatsoever. This cannot be fixed in the SOP chain — binding a material in USD needs UsdShadeMaterial prims, and a SOP cannot author them. It is LOP work, and the pattern already exists in-house in the UXO project: 855 MaterialX documents bound through a Looks scope.

GATE · an asset opens textured in usdview · prototypes namespaced so two assets can share a stage
07WEEK 6–7

Presentation and documentation

Install the 150 icons that already exist and are simply not attached — no redesign needed, since Houdini 22 explicitly exempts node icons from its new theming. Write the missing Help sections, unify the Tab-menu placement, and generate a per-tool reference from the audit data rather than by hand.

GATE · every shipped tool has an icon, a Help section and a correct menu entry
08WEEK 7–8

Release preparation

Remove dead tools, verify the library loads clean from a cold install with no missing types, test the companion Unreal project end to end, and write the customer-facing installation and conventions documentation.

GATE · cold install cooks every tool with zero errors and zero missing references
03

Principles this plan is built on

Fail loudly, never plausibly

Every defect found in this audit shared one shape: plausible output, no error. An empty transfer field that silently stripped every attribute. A VEX read of a missing attribute returning zero. An exception that quietly abandoned a batch at item 93. The standard tooling now errors by default rather than warning, because a warning inside a 12,000-node cook is invisible.

Decisions are the scarce resource, not effort

15 scripted jobs cover most of the volume. The 33 decisions are what actually take time, and they are the part that cannot be delegated — which spelling is canonical, which version ships, which tools are dead. The plan is sequenced so those arrive in batches rather than interrupting the mechanical work.

Breaking changes go early or never

Zone names become Unreal component names and USD prim names. Type names are referenced by every existing scene. Once customers build against them, they are frozen. Everything breaking is front-loaded into weeks 2 and 3 for that reason.
