What this is

A Houdini toolkit for procedural architecture and city generation — 155 tools built over years of production work, heading for commercial release with a companion Unreal project.

The differentiator is not breadth. It is that nothing here is baked. A kit of models gives you a building; change its proportions and the windows stretch, the mouldings smear and the brick scales wrong. A generator gives you a building that is correct at any size, because the geometry is derived from parameters and real-world standards rather than frozen at authoring time.

Their assets are baked and hardcoded, have crappy textures and do not look like real architecture for the most part. They also give an artist very little control and are not very well optimized. On kitbash3d.com — and the inverse of that list is the product spec

So the four claims the whole project has to earn are: procedural, standards-based, artist-controlled, optimised. Everything in this handbook is in service of one of those, and the credibility comes from the tools having survived real production rather than having been designed for a storefront.

What the size collapse actually was

AB.CrystalGenerator.1.0.hda was 236 MB — 84% of the library — and none of it was needed. No embedded images at all: 227 MB sat in one node's stashed geometry, on a node that was bypassed. The tool now weighs 0.07 MB, all 417 inner nodes intact.

That is worth stating because the diagnosis generalises: look at whether the weight is in Contents.gz or in image sections before assuming it is textures. Those need completely different fixes.

File size is not a defect signal on every tool

ModulesGothic (21 MB) and PlantOnsFuturistic (3.5 MB) also carry heavy embedded geometry — and there it is the product. They are Library-class tools whose baked models are the content. The real question is never "is the file big" but "is the payload content or leftover".

The design system

Three orthogonal axes

The distinction that keeps the whole catalog coherent:

AxisWhat it answersWhat it drives
TypologyWhat the thing is, functionallyDimensions, from standards
StyleHow it is articulatedOrnament and subdivision — never dimensions
VariationIts conditionWear, sag, patching, replacement

The test that keeps them clean: changing style must not change the dimensions. A six-panel and a single-light residential door are both 36 × 80 — which is exactly why a builder can swap them. It follows that mansard is a typology, not a style: it changes the break height and the two pitches. Second Empire is the style.

Four patterns that keep recurring

These were not planned. Each was discovered solving one problem and then turned out to solve the next three, which is the strongest signal available that they are right.

1 · Catalog — a CSV of real specifications plus a lookup

Used four times now: SignLibrary (1,383 signs), HardwareMaker, the WM moulding chart, and steel sections. The class selects a column, not a scale factor — MUTCD gives a different absolute size per sign per class, so a stop sign at freeway size is not a conventional one multiplied. A system built on scaling gets this wrong; a lookup table cannot.

2 · Grammar — composable elements instead of enumerated shapes

Every moulding on the WM chart is a stack from a ten-element vocabulary: fillet, bead, ovolo, cove, scotia, cyma recta, cyma reversa, quirk, chamfer, round. So a profile is one editable string, not a hand-built network. The same insight applies to roof sections, because a roof section drawn in (run, rise) is a moulding profile.

3 · Classification — compute the parts, never name them

The footprint tools hand-authored a group per wall and per corner, so the node count scaled with edge count: a 4-edge rectangle needed 8 groups, a 6-edge L needed 12, and adding a U meant hand-authoring 16. Measuring turn angle and convexity per vertex produces the same structure for any polygon.

⭐ The same layer serves roofs: w = cot θ makes per-edge pitch a per-edge weight, so a footprint's edge classification is a roof's input.

4 · Processor — take a surface and dress it

RooftopProcessor is to a roof what SidewalkProcessor is to a sidewalk. Generalised, this is the decorating product — the thing KitBash sells that AssetBash does not yet do systematically, and the step that turns a shape into a place.

Roofs

designed, not built

Four operators span eighteen named forms. SKELETON absorbs fourteen of them with no branching.

Key
w = cot θ — per-edge pitch is per-edge wavefront speed. Set two weights to zero and a hip becomes a gable.
Leverage
polyexpand2d already computes the weighted straight skeleton natively, and appears in exactly one of 155 tools. So this is wiring, not implementing.
Watch
Rectilinear footprints are the degenerate case, not the general one — deterministic tie-breaking is a prerequisite.

Zones, materials & Copernicus

the named gap
Scope
87 tools need s@name zones; 171 zones unbound.
⚠ Trap
s@name does two conflicting jobs. A packing key must be unique per piece; a shading zone must be shared across pieces. Of 406 distinct values, 234 are packing keys. Hence ab_zone.
Note
Zone names become USD prim names and Unreal component names, so renaming one is a breaking change.

Research

The tools are only as good as what they know. These are the standing research efforts — each one exists to turn something architects know into something a system can compute.

All three run as persistent agents with their own briefs, so a question asked twice gets answered the same way. Every one is held to the same rule: a figure that was recalled rather than read from a source is marked unverified. That is not caution for its own sake — a fabricated "verbatim" code quotation was produced and caught during the roof work, and the marking is what caught it.

Building plans — houses, commercial, towers

delivered

The most ambitious brief so far, and the one that decides whether this becomes a building generator or an architectural simulator.

Question
What actually organises a plan — and what would it take to generate one that reads as designed rather than extruded?
Two halves
The regularities — column grids and why parking so often sets the grid for everything above, core-to-perimeter lease span, floor plate efficiency, and egress as plan topology. And the architects who break them knowingly — MAD, OMA/Koolhaas, Morphosis, and Le Corbusier's Five Points.
⭐ The key idea
The free plan. Once structure is separated from enclosure, partitions are no longer bound to the structural grid — which is exactly the separation a procedural system needs between frame and infill.
The classical root
Vitruvius, the Roman domus and the basilica. Not history: the Palladian shape grammar is Palladio formalised and Palladio is Vitruvius received, so the oldest material connects directly to the most computational. Symmetria sizes a building from one module by ratio — a parametric system written in the first century BC, and the same move Corbusier makes with the Modulor.
⭐ The taxonomy
Three layers that compose in a fixed order and never the reverse: GRID → CORE → PARTITION, each constraining the next. Across them six plan types — house, bar/row, commercial plate, tower, top-lit hall, and Koolhaas's "Big".
The distinction
In a house the plan is the design; in a commercial plate the plan is deliberately not designed. An office floor that arrives full of authored rooms is wrong — a rule a naive generator gets backwards.
Derivable
Eleven inputs yield the column grid, plate depth, core size and position, stair count and separation, corridor topology, wet-wall positions, taper and roof form. Not derivable: the room adjacency graph, room proportions, the programme, and all irregularity. Those are catalog, always.
⭐ Scoring
Space syntax integration turns "is this plan any good" into a computable question — and the evaluator contains no learning. Every stage is a SOP network, so plans can be scored without training anything.
⚠ Datasets
RPLAN is ~70% near-duplicates and its licence restricts use, not just redistribution — unusable for anything shippable. LIFULL refuses company applicants. ResPlan (CC BY 4.0) is the one to use: mine it for the catalog, generate with rules, train nothing.
Where
research/building_plans.md — 2,680 lines, 66 cited figures, 48 marked second-hand, 8 unverified and deliberately unused

Two findings that reframe work already planned

Vitruvius's proportions are a graduated band table, not constants. The atrium wings are 1/3 of the length at 30–40 ft but 1/5 at 80–100 ft — literally the same lookup shape as SignLibrary's SizeClass and corner-treatment-by-angle-band. He solved "one ratio does not scale" by tabulating it, in the first century BC. And he breaks his own rule in his own worked example: at Fano the columns are 50 ft where the rule gives 20, and he omits two for a sightline to a neighbouring temple. The canonical source is less rigid than a naive generator would be.

The atrium office building is a basilica. One operator with three parameters generates the Roman basilica, the church, the market hall, the sawtooth already in our roof work, and the atrium tower.

Two gaps we are positioned to fill

Rectangular dualisation makes plans from adjacency graphs; code checking evaluates finished plans. Nobody has published dualisation constrained by egress. Nor has anyone joined straight-skeleton navigation graphs to conformant travel-distance checking — and we already own the skeleton machinery from the roof work. Both are publishable, not merely buildable.

How we work

This section is part of the product, not process overhead. "Standards-based" is only credible if the standards are actually checked, and the discipline below is what makes that claim defensible.

Measure the before state, then change

A materials migration was once reverted because 31 apparent failures turned out to be pre-existing breakage nobody had baselined — the rewrite could not be judged, because there was no before. Every rewrite since carries an oracle captured first: 135 cases for the extrusions, 162 for the footprints, 8 for the Skyscraper repoint.

An assertion must be able to fail

A footprint test reported 8 of 8 passing while nine real defects sat in the code. It asserted winding by reading a value the code had just forced positive — so it could not fail for any valid input. Every check now names the defect that would trip it; a check whose defect cannot be named is decoration.

Measuring the wrong thing is the most common failure

Three times in one day: a normal test using a centroid dot-product on a concave shape; arc radius measured from the centroid of the arc points rather than the circumcentre, making a perfect arc look 83% out; a zero-length closing edge reporting a self-intersection on every shape. Check the method before believing the number.

Adversarial review before anything ships

A dedicated reviewer whose job is to refute — hunting tests that cannot fail, measurements that do not measure what they claim, and numbers stated as fact that were never read from a source. It found nine real defects in work that looked finished, and one fabricated "verbatim" code quotation that had been caught and discarded mid-research.

Known problems

The footprint generator has issues Jordan has seen and I have not

It is installed and every numeric check passes — parity, sweep, and the Skyscraper canary all clean. That is precisely what makes it interesting: the checks did not catch it. Rollback is one wire inside the HDA, or the tag.

Six tools depend on types that exist only in a session

ModulesGothic, RoadTerrainGenerator, ModulesClassical, BlocksRGB, CrystalGenerator, StairGenerator. A clean session reports six unresolved types where a session carrying them reports zero — so health checks must run in a clean session or they lie.

The orphan triage is 108 places to look, not 108 bugs

A parm family that is part channel-referenced and part typed-literal is the fingerprint that made the Square Tube broken for years. But spot-checking finds real false positives — a grid.sizex of 4096/2048/1024/512 is a deliberate resolution ladder. The number narrows 12,000+ nodes to ~108 worth opening.
